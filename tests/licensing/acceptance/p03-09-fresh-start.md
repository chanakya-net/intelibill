# P03-09 paid time starts when access can be restored

- A paid conversion replaces the selected trial at the paid start. The trial and any extension receipts remain in history. The paid end is one calendar month or year from the new anchor.
- An expired paid package can buy a fresh period for the same named coverage. Checkout discloses the restricted gap and estimated dates. The verified receipt shows the actual paid dates.
- Trading or security restriction can hold money without granting access. Retry the original verification after an independent release. A manual confirmation can be retried using its original request and receipt.
- A late confirmation of an on-time renewal retains the accepted period. A Licensing Manager can separately link an approved complimentary interval to the fulfilled order. The merchant sees the interval and grant reference separately from paid dates.
- Verified payment, term fulfilment and acknowledged access are separate. The licensing service publishes signed snapshots, and merchant acknowledgement advances access status.

Build the merchant app with `bun run build` in `src/frontend`. Run `P0309Tests` on PostgreSQL and `P0309BrowserTests` with `P0309_RUN_BROWSER=1` and a writable `P0309_EVIDENCE_DIR`. The browser fixture uses the shipping Angular build, real loopback APIs, PostgreSQL and the Development gateway. It exercises Trading restriction and a fixture-supplied release. The typed Closed refusal is tested at the policy boundary because this phase has no closure writer. The fixture does not contact a live provider.
